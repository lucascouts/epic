# Implementation Plan - Git-Aware Lifecycle

## Overview

Three groups: the read-only detection script first (it has no dependencies and everything else consumes it), then its surfacing in LIST/validate, then the supersede operation (which depends on story 004's `superseded` state and `[~] (superseded-by:)` qualifier, and offers story 005's archive at the end). The no-storage rule is absolute: no SHA, branch name or merge-base is ever written into artifacts. Group 4 was added by refinement after the story's own `validate` run: it closes a real contract break (a control character in a commit subject makes the emitted JSON unparseable while the script still exits 0), covers the one preflight state supersede depends on, and records the deviations the audit found missing. Group 5 came from the second `validate`, which raised two stale artifact texts (merged into story.md and design.md by that same refinement, so they carry no task) and exactly one code defect: a branch merged under both a local and a remote-tracking ref is reported twice. Group 6 came from the third `validate`, and its subject is group 5's own work: the dedup was wrong on both of its predicates, and the R3.5 amendment that shipped alongside it collided with R3.4. Group 5 had inverted test-first; the audit showed the cost precisely (its case 4 asserted the benign half of its own rule, and the hostile half was the defect), so group 6 restores the order — tests authored from the amended requirement, Red confirmed, then an Executor implementing against frozen tests.
